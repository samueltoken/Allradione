# 0.2.4 재생 실패 조사

2026년 11월 13일 대한민국 인터넷 회선에서 조사했다. 이전 버전의 전체 점검에서는 53,628개 등록 항목 가운데 재시도 후에도 5,239개에서 송출 데이터를 확인하지 못했다. 이 중 실패 원인이 일반 연결 오류로 남은 1,963개를 이번 버전의 재생 경로로 다시 검사했다.

| 재검사 결과 | 등록 항목 수 |
| --- | ---: |
| 송출 데이터 수신 | 1,375 |
| 서버의 요청 횟수 제한 | 378 |
| 응답 시간 초과 | 143 |
| 일반 연결 오류 | 63 |
| 연결 초기화 | 4 |

재검사 때 서버 상태와 요청량도 달랐다. 1,375개는 이번에 음성 데이터를 받은 건수다. 별도 데스크톱 재생기에서 음원 해석과 재생 시간 진행까지 확인한 방송은 NHK 출력 11, RADIO BOB!의 80s Christmas, MBC충북 표준FM, 부산영어방송이다.

## 무엇이 실패했나

- NHK의 예전 GS2 주소는 첫 목록을 열어 줬지만, 그 아래의 주·예비 재생 목록 모두 접근을 거절했다. 지역 또는 편성 때문인지는 확인되지 않았다. NHK 공식 플레이어의 송출표를 대조하니 등록소가 ‘-2’라고 부르던 주소가 실제 출력 11이었다. 두 항목의 표기를 바로잡았다. 한국어 방송은 당시 편성된 출력 번호로 연결한다. [NHK 공식 송출표](https://livepl-radio.nhkworld.jp/hlslive_radio.json) · [공식 플레이어 코드](https://www3.nhk.or.jp/nhkworld/common/js/nw_radio_live_play.js)
- RADIO BOB!, FluxFM, VRT 등 일부 송출 서버는 응답 첫 줄의 끝에 줄바꿈 문자 하나만 보냈다. 기존 앱에서는 음성을 받기 전에 이 응답을 거부했다. 성공한 연속 음성 응답에 한해 이 형식을 읽도록 고쳤고, 서로 다른 송출 호스트 10곳에서 음성 데이터를 받았다.
- 경로가 사라진 주소, 접근 거절, 요청 횟수 제한, 서버 인증 오류, 응답 지연도 있었다. 시간이나 회선에 따라 결과가 달라지는 경우가 있어 사용자가 직접 다시 시도할 수 있다.

## 다른 플레이어와 등록소

Music Assistant는 Radio Browser에서 실패로 표시된 항목을 기본 탐색에서 걸러내고, 재생할 때 방송 ID로 정보를 조회해 최종 주소 또는 원래 주소를 사용한다. Radio Browser의 성공 여부는 등록소가 최근 점검한 결과다. 청취자의 현재 위치에서 음성까지 도달한다는 보장은 없다. Allradione는 실제 재생 결과를 해당 기기에 기록하고, 방송사가 별도로 주소나 편성 정보를 공개한 경우 그것도 활용한다. [Music Assistant 구현](https://github.com/music-assistant/server/blob/dev/music_assistant/providers/radiobrowser/__init__.py) · [Radio Browser의 데이터 항목](https://docs.radio-browser.info/)
